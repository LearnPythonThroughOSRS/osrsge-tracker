# Lovable Prompt 4 — Fix API key authentication mismatch

Paste everything below the line into Lovable chat.

---

Bug: API keys generated by the generate-api-key function are rejected
with 401 by trades-sync and offers-sync. Verified with curl: a key
freshly generated in the dashboard (format `osrsge_<48 hex chars>`)
gets {"ok":false,"error":"unauthorized"} from offers-sync.

The cause is almost certainly a hashing mismatch between the two code
paths. Please check and fix so that BOTH use the exact same bytes and
encoding:

1. In generate-api-key: take the FULL key string exactly as returned to
   the user (including any `osrsge_` prefix), compute SHA-256, encode
   the digest as lowercase hex, store that in api_keys.key_hash.
2. In trades-sync and offers-sync: take the FULL bearer token exactly
   as received (after stripping only the leading "Bearer "), compute
   SHA-256, encode as lowercase hex, and look that up in
   api_keys.key_hash.

Common mistakes to rule out:
- One side hashing only part of the key (e.g. without the osrsge_
  prefix) while the other hashes the whole string.
- One side encoding the digest as base64 while the other uses hex.
- Trimming/whitespace differences.
- Looking up the wrong column.

After fixing, please test end-to-end yourself: call generate-api-key
for a test scenario, then call offers-sync with
`Authorization: Bearer <that key>` and body
{"playerName":"Self Test","offers":[]} and confirm it returns
{"ok":true} — then delete any Self Test rows. Existing stored key
hashes may be invalid if generate-api-key was the broken side; if so
say so, and I will regenerate my key afterwards.
